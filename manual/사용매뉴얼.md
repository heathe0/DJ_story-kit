**Story Kit 버전 0.8**

데이터 저널리즘 수업에서 사진, Flourish 차트, 구글 시트 표, 구글 어스 지도, 유튜브 영상, 스크롤리텔링이 들어간 인터랙티브 기사를 직접 만들도록 돕는 웹 편집기의 사용 매뉴얼입니다. 설치와 가입 없이 크롬이나 엣지에서 파일 하나를 열어 쓰고, 완성본은 HTML 파일 한 개로 내보내 웹에 올립니다.

| 읽는 사람 | 먼저 볼 장 |
|---|---|
| 기사를 만드는 학생·기자 지망생 | 1장 시작하기 → 2~4장 입력 방법 → 5장 저장과 발행 → 6장 점검 |
| 수업을 운영하는 교수·강사 | 7장 수업에서 쓰기 → 8장 기사 기획 가이드 |

# 1. 시작하기

편집기는 `index.html` 파일 하나로 되어 있습니다. 설치도, 회원 가입도 필요 없습니다. 크롬이나 엣지에서 파일을 열면 바로 씁니다.

1. `index.html` 파일을 내 컴퓨터에 내려받습니다.
2. 파일을 크롬 창으로 끌어다 놓거나, 더블클릭해서 엽니다.
3. 처음 열면 **예시 기사**가 들어 있어요. 숫자와 지명은 모두 연습용 가상 데이터입니다. 하나씩 고치거나 지워 가며 내 기사로 바꾸세요.
4. 처음부터 쓰고 싶으면 위쪽 막대의 **새 기사**를 누릅니다. 예시가 다시 필요하면 **예시 불러오기**를 누르면 돼요.

## 화면 구성

| 영역 | 하는 일 |
|---|---|
| 위쪽 막대 | 새 기사, 예시 불러오기, 작업 파일 열기·저장, 발행하기, 도움말 |
| 왼쪽 편집 창 | 표지·기사 정보 → 꾸미기 → 블록들 → 크레딧 순서로 내용을 입력 |
| 오른쪽 미리보기 | 입력한 내용이 실제 기사 모양으로 바로 보임. 위쪽 단추로 PC 화면·휴대폰 화면 전환 |

- 미리보기에서 문단이나 사진을 누르면 왼쪽에서 그 블록이 열립니다.
- 반대로 왼쪽 블록을 열면 미리보기가 그 위치로 이동해요.
- 창이 좁으면(노트북 화면을 반으로 나눴을 때 등) 위쪽에 **편집 / 미리보기** 전환 단추가 생깁니다.
- 입력 내용은 이 브라우저에 자동 저장돼요. 오른쪽 위에 마지막 저장 시각이 표시됩니다. 단, 다른 컴퓨터로 옮기려면 반드시 **작업 파일 저장**을 해야 합니다(5장).

# 2. 표지, 꾸미기, 크레딧

왼쪽 편집 창의 맨 위 두 칸과 맨 아래 한 칸은 모든 기사에 하나씩만 있는 고정 칸입니다.

## 표지와 기사 정보

| 칸 | 쓰는 법 |
|---|---|
| 매체 이름 | 기사 맨 위 막대 왼쪽에 표시. 예: 광운 데이터저널리즘랩 |
| 머리말 | 제목 위 작은 줄. 기획 이름이나 분야. 예: 데이터로 본 서울 |
| 기사 제목 | 줄을 바꾸면 표지에서도 줄이 바뀜. 두 줄 안쪽을 권장 |
| 부제·리드 | 제목 아래 2~3문장. 기사의 핵심 발견을 숫자와 함께 |
| 표지 형태 | 사진 위에 제목(풀스크린) / 제목과 사진 나란히 / 글자 중심 |
| 표지 사진 | [사진 올리기] 또는 끌어다 놓기. 자동으로 줄여서 파일에 넣음 |
| 기자 | 한 줄에 한 명, `이름 이메일` 순서. 이메일에는 링크가 걸림 |
| 팀 이름·발행일 | 제목 아래 기자 줄에 함께 표시 |

- 표지 사진이 없으면 강조색이 은은하게 번지는 어두운 표지가 됩니다.
- 사진 위에 제목을 얹을 때는 사진 아래쪽이 너무 밝지 않은 것을 고르세요. 제목은 사진 아래쪽에 놓입니다.

## 꾸미기

| 칸 | 쓰는 법 |
|---|---|
| 배경색 | 추천 색 6개 중에 고르거나 직접 고름. 배경을 어둡게 하면 글자색이 자동으로 밝아짐 |
| 강조색 | 형광펜, 머리말, 큰 숫자, 맨 위 진행 막대 색. 추천 색 6개 또는 직접 고름 |
| 제목 글꼴 · 본문 글꼴 | 나눔고딕(기본), 맑은 고딕, 본고딕, 나눔명조, 본명조, 고운바탕, 내가 올린 글꼴 중 선택 |
| 글꼴 파일 올리기 | woff2·woff·ttf·otf 파일을 올리면 "내가 올린 글꼴"로 제목과 본문에 바로 적용. 12MB까지 |
| 본문 글자 크기 | 14~24px (기본 18px). 사진 설명·표·상자 글자도 같은 비율로 바뀜 |
| 제목 크기 | 70~130% (기본 100%). 기사 제목, 소제목, 인용, 큰 숫자에 적용 |

- 기본 글꼴 **나눔고딕**은 웹 글꼴이라 윈도·맥·휴대폰 어디서나 같은 모양으로 보입니다. 맑은 고딕은 윈도에만 있어서 맥과 휴대폰에서는 비슷한 기본 고딕(애플 SD 산돌고딕 등)으로 보입니다.
- **올린 글꼴**은 기사 파일 안에 함께 들어가므로 독자 컴퓨터에 그 글꼴이 없어도 똑같이 보입니다. 대신 한글 글꼴은 수 MB라 기사가 무거워지니, 가능하면 용량이 작은 woff2 파일을 쓰세요.
- 웹 게시(임베딩)가 허용된 글꼴만 올리세요. 무료 글꼴도 사용 범위가 정해져 있으니 배포처의 라이선스를 확인하세요.

## 크레딧 · 출처

- **제작진**: 한 줄에 하나씩 `역할: 이름`. 예: `데이터 분석: 김하늘`
- **자료 출처**: 한 줄에 하나. 주소를 쓰면 자동으로 링크가 됩니다.
- **맺음말·바로잡습니다**: 기사 끝에 덧붙일 말이나 정정 안내.
- **공유 미리보기 이미지 주소**: 카카오톡·SNS에 링크를 보낼 때 뜨는 그림. 이미 웹에 올라가 있는 이미지 주소만 쓸 수 있어요. 비워 두면 그림 없이 제목과 부제만 뜹니다.

# 3. 블록 사용법

기사 본문은 블록을 쌓아서 만듭니다. 맨 아래 **블록 추가**를 누르거나, 블록과 블록 사이에 마우스를 올리면 나오는 **+** 단추로 그 자리에 끼워 넣을 수 있어요. 블록 오른쪽 단추로 위·아래 이동, 복제, 삭제를 합니다.

| 블록 | 묶음 | 언제 쓰나 |
|---|---|---|
| 소제목 | 글 | 이야기의 장을 나눌 때. 위에 작은 머리 표기(예: 1부 · 소득)를 달 수 있음 |
| 본문 | 글 | 문단. 굵게·형광펜·기울임·링크 가능 |
| 인용 | 글 | 취재원의 핵심 발언을 크게 |
| 설명 상자 | 글 | 분석 방법, 용어 풀이. "접어 두기"를 켜면 누를 때만 펼쳐짐 |
| 구분선 | 글 | 장면 전환. 짧은 선 / 점 세 개 / 여백 |
| 사진 | 미디어 | 사진 한 장 + 설명 + 출처 |
| 사진 묶음 | 미디어 | 사진 2~4장을 나란히 |
| 유튜브 | 미디어 | 영상 (4장 참고) |
| 숫자 강조 | 데이터 | 큰 숫자가 0부터 올라가는 카운트업, 최대 4개 |
| Flourish 시각화 | 데이터 | 차트·지도 (4장 참고) |
| 구글 시트 표 | 데이터 | 표 (4장 참고) |
| 구글 어스 · 지도 | 데이터 | 위성 지도와 3D 보기 단추 (4장 참고) |
| 스크롤리텔링 | 인터랙티브 | 그림은 화면에 고정, 글 카드가 지나가며 장면이 바뀜 |
| 기타 임베드 | 인터랙티브 | Datawrapper, 설문, 지도 등 iframe 코드 (4장 참고) |

## 본문 서식

본문 칸 위의 단추를 눌러도 되고, 직접 기호를 써도 됩니다.

| 쓰는 법 | 결과 |
|---|---|
| `**굵게**` | **굵게** |
| `==형광펜==` | 강조색 형광펜 |
| `*기울임*` | *기울임* |
| `[글자](https://주소)` | 링크 |
| 빈 줄 한 번 | 새 문단 |
| 줄 앞에 `- ` | 목록 |

## 사진

- 사진은 자동으로 알맞은 크기로 줄여 기사 파일 안에 넣습니다. 따로 웹에 올릴 필요가 없어요.
- **대체 텍스트**는 시각장애인용 화면 낭독기가 읽어 주는 설명입니다. 사진에 무엇이 보이는지 한 문장으로 꼭 쓰세요.
- **폭**: 본문 폭 / 넓게 / 화면 가득. 현장감이 중요한 사진은 "화면 가득"을 써 보세요.
- 사진이 많을수록 기사 파일이 커집니다. 발행 화면에 크기가 표시돼요.

## 숫자 강조

- **숫자** 칸에 숫자만 쓰면(예: `1,600`, `8.4`) 독자가 그 위치에 오면 0부터 올라갑니다. 쉼표와 소수점 자리는 그대로 지켜져요.
- `1억 6000만`처럼 글자가 섞이면 효과 없이 그대로 표시됩니다. 이럴 땐 숫자 `16,000`, 단위 `만 회`처럼 나눠 쓰세요.

## 스크롤리텔링

뒤의 그림은 화면에 고정되고, 글 카드만 위로 지나가며 그림이 바뀌는 방식입니다. 경향신문 「33개 지표로 살펴본 한국사회 불평등 보고서」의 차트 하이라이트, 「가지도 않을 표를 사는 사람들」의 데이터 전환과 같은 원리예요.

1. **뒤에 고정할 그림**을 고릅니다. 사진·그래픽 또는 Flourish 스토리.
2. 사진·그래픽이면 단계마다 그림을 올립니다. 그림을 비워 둔 단계는 앞 그림이 그대로 유지돼요.
3. 각 단계의 **글 카드**를 2~4문장으로 씁니다.
4. 차트·지도처럼 잘리면 안 되는 그림은 **그림 맞춤**을 "잘리지 않게"로 바꿉니다.
5. **글 카드 위치**(왼쪽·가운데·오른쪽)는 그림의 빈 쪽으로 정하세요.

- 효과를 살리는 요령: 같은 차트에서 **강조만 바꾼 그림**을 여러 장 만드세요. 예) 1단계 전체 회색, 2단계 서울만 빨강, 3단계 서울·부산 빨강.
- Flourish 스토리를 고르면 단계마다 "보여 줄 슬라이드 번호"를 적습니다. 카드가 지나갈 때 그 슬라이드로 넘어가요.

# 4. 임베드 주소 얻는 법

주소를 붙여넣으면 칸 아래에 **✓ 인식됨** 또는 **✕ 인식하지 못했어요**가 바로 뜹니다. 초록 체크가 뜨면 성공이에요.

## Flourish 시각화

1. Flourish에서 차트를 완성한 뒤 오른쪽 위 **Export & publish**를 누릅니다.
2. **Publish to share and embed**를 눌러 게시합니다.
3. 나온 링크(`https://public.flourish.studio/visualisation/…`)를 복사해 붙여넣습니다. **Embed code**를 통째로 붙여넣어도 됩니다.
4. **PC 높이**와 **휴대폰 높이**를 조절해 차트가 잘리지 않게 합니다. 범례가 많은 차트는 휴대폰 높이를 더 크게.
5. **데이터 출처**를 꼭 적으세요. 비워 두면 발행할 때 점검표에 나옵니다.

- 편집 화면 주소(`app.flourish.studio/…/edit`)를 넣으면 "게시했는지 확인하세요" 안내가 뜹니다. 게시 전에는 독자에게 보이지 않아요.

## 구글 시트 표

두 가지 방식이 있습니다. **기사 스타일 표**를 추천해요. 기사 디자인에 맞춘 깔끔한 표가 되고, 시트를 나중에 지워도 표가 남습니다.

1. 구글 시트에서 **파일 > 공유 > 웹에 게시**를 누르고 **게시**합니다.
2. 나온 링크를 **구글 시트 주소** 칸에 붙여넣습니다.
3. **시트에서 데이터 가져오기**를 누르면 아래 **표 데이터** 칸이 채워집니다.
4. 가져오기가 안 되면: 시트에서 표 영역을 드래그해 복사(Ctrl+C)하고 **표 데이터** 칸에 붙여넣으면 끝입니다.

- 첫 줄은 제목 줄이 됩니다. 숫자만 있는 열은 자동으로 오른쪽 정렬돼요.
- 줄이 많으면 표 안에서 스크롤되고, 제목 줄은 위에 고정됩니다.
- **구글 시트 화면 그대로 넣기**를 고르면 시트 화면이 기사 안에 들어갑니다. 시트를 고치면 기사에도 바로 반영되지만, 디자인은 구글 시트 모양 그대로예요.

## 구글 어스 · 지도

구글 어스 웹은 다른 사이트 안에 직접 넣을 수 없게 막혀 있습니다. 그래서 이 블록은 **같은 위치의 위성 지도**를 기사에 넣고, 아래에 **구글 어스에서 3D로 보기** 단추를 달아 줍니다. 독자가 단추를 누르면 구글 어스의 그 장면이 새 창에서 열려요.

1. earth.google.com 에서 보여 주고 싶은 장소와 각도로 이동합니다.
2. 왼쪽 메뉴의 **링크 아이콘**(공유)을 눌러 링크를 복사합니다. 주소창의 주소를 복사해도 됩니다.
3. 블록 칸에 붙여넣으면 위도·경도·확대 정도가 자동으로 채워져요.
4. **지도 종류**(위성 / 위성+지명 / 일반 지도), **핀 꽂기**, 높이를 정합니다.

- 구글 지도 주소나 `37.5665, 126.9780` 같은 좌표만 넣어도 됩니다.
- 구글 지도의 **공유 > 지도 퍼가기** 코드를 붙여넣으면 그 지도를 그대로 넣습니다.
- 구글 어스 스튜디오로 만든 비행 영상은 유튜브에 올린 뒤 **유튜브 블록**으로 넣으세요.

## 유튜브

1. 영상 아래 **공유**를 누릅니다.
2. 특정 장면부터 틀고 싶으면 **시작 시간**에 체크합니다.
3. **복사**한 주소를 붙여넣습니다. 쇼츠 주소는 세로 화면으로 들어가요.

- 내 컴퓨터에서 연 편집기 미리보기에서는 "오류 153"이 뜰 수 있습니다. 유튜브가 웹 주소가 없는 페이지에서 재생을 막기 때문이에요. 발행해서 웹에 올리면 정상 재생됩니다.

## 기타 임베드

Datawrapper 차트, 구글 설문, 카카오맵 등 `<iframe …>` 코드를 주는 서비스는 대부분 이 블록으로 넣을 수 있습니다.

- 코드를 통째로 붙여넣으면 편집기가 주소(src)와 높이만 골라 씁니다.
- `<script>`가 필요한 코드(반응형 높이 조절 등)는 실행되지 않아요. 대신 PC·휴대폰 높이를 직접 정하세요.
- https:// 로 시작하는 주소만 받습니다.

# 5. 저장과 발행

파일은 두 종류입니다. **작업 파일(.json)** 은 다시 고치기 위한 원본이고, **발행 파일(index.html)** 은 독자가 보는 완성본입니다. 둘 다 꼭 보관하세요.

| 파일 | 만드는 단추 | 용도 |
|---|---|---|
| `기사제목.storykit.json` | 작업 파일 저장 | 이어서 고치기, 다른 컴퓨터로 옮기기, 조원과 주고받기 |
| `index.html` | 발행하기 → HTML 파일 내려받기 | 웹에 올릴 완성본. 사진까지 한 파일에 들어 있음 |

## 자동 저장과 작업 파일

- 편집기는 이 컴퓨터의 이 브라우저에 자동 저장합니다. 같은 컴퓨터에서 파일을 다시 열면 쓰던 기사가 그대로 나와요.
- 다른 컴퓨터, 다른 브라우저, 시크릿 창에서는 자동 저장이 보이지 않습니다. 실습실 컴퓨터를 쓴다면 끝나기 전에 꼭 **작업 파일 저장**을 하세요.
- 다음에 이어 쓸 때는 **작업 파일 열기**로 .json 파일을 고릅니다.
- 조별 작업: 한 사람이 저장한 .json을 메신저나 드라이브로 넘기면 다른 사람이 열어서 이어 쓸 수 있어요. 동시에 같이 고칠 수는 없으니 차례를 정하세요.

## 발행하기

**발행하기**를 누르면 먼저 점검 결과가 나옵니다. 제목·기자 누락, 대체 텍스트가 없는 사진, 주소가 없어 빠질 임베드, 출처가 없는 차트를 알려 줘요. 고친 뒤 **HTML 파일 내려받기**를 누릅니다.

- 발행본에서는 비어 있는 블록과 주소가 인식되지 않은 임베드가 자동으로 빠집니다. 미리보기의 점선 상자는 발행본에 나오지 않아요.
- 파일 크기가 15MB를 넘으면 경고가 뜹니다. 사진 수를 줄이세요.

## 웹에 올리기 ① Netlify Drop (가장 쉬움)

1. 바탕화면에 새 폴더를 만들고, 내려받은 `index.html`을 넣습니다.
2. 브라우저에서 `app.netlify.com/drop` 에 접속해 무료로 가입합니다.
3. 폴더를 통째로 화면에 끌어다 놓습니다. 몇 초 뒤 기사 주소가 생겨요.
4. 사이트 설정에서 주소 앞부분을 기사 이름으로 바꿀 수 있습니다.
5. 고친 뒤 다시 올릴 때는 그 사이트의 **Deploys** 화면에 폴더를 다시 끌어다 놓습니다. 주소는 그대로예요.

## 웹에 올리기 ② GitHub Pages

1. GitHub에서 새 저장소(repository)를 **Public**으로 만듭니다.
2. **Add file > Upload files**로 `index.html`을 올립니다.
3. **Settings > Pages**에서 Branch를 `main`으로 고르고 **Save**합니다.
4. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 으로 기사가 열립니다.

- 같은 저장소에 다시 올리면(같은 이름으로 덮어쓰기) 기사가 갱신됩니다.
- 유튜브·Flourish·지도는 웹에 올린 기사에서 가장 정확하게 보입니다. 발행 전에 꼭 웹 주소로 열어 확인하세요.

# 6. 자주 겪는 문제와 발행 전 점검

| 증상 | 원인 | 해결 |
|---|---|---|
| 파일을 다시 열었더니 쓰던 기사가 없음 | 다른 컴퓨터·브라우저·시크릿 창에서 열었음 | **작업 파일 열기**로 저장해 둔 .json을 연다 |
| 미리보기 유튜브에 "오류 153" | 내 컴퓨터에서 연 페이지라 유튜브가 재생을 막음 | 발행해서 웹에 올리면 정상 재생 |
| Flourish 자리가 비어 있음 | 게시(Publish)를 안 했거나 편집 주소를 넣음 | Flourish에서 게시 후 나온 링크로 바꾼다 |
| [시트에서 데이터 가져오기] 실패 | 시트가 웹에 게시되지 않았거나 비공개 | 웹에 게시하거나, 표를 복사해 직접 붙여넣는다 |
| 차트·지도가 휴대폰에서 잘림 | 높이가 부족함 | 블록의 **휴대폰 높이**를 늘리고 미리보기를 **휴대폰**으로 확인 |
| 스크롤리텔링 그림이 잘림 | 그림 맞춤이 "화면 가득" | **잘리지 않게**로 바꾼다 |
| 숫자가 올라가지 않음 | 숫자 칸에 글자가 섞임 | 숫자와 단위를 나눠 쓴다 |
| 발행 파일이 너무 큼 | 사진이 많거나 GIF가 큼 | 사진 수를 줄이거나 GIF 대신 유튜브·사진을 쓴다 |
| 미리보기가 안 바뀜 | 자동 새로고침이 꺼짐 | 미리보기 위 **새로고침**을 누르거나 자동 새로고침을 켠다 |

## 발행 전 점검표

- [ ] 제목과 부제가 기사의 핵심 발견을 숫자와 함께 말한다
- [ ] 기자 이름, 팀 이름, 발행일이 들어 있다
- [ ] 모든 사진에 대체 텍스트와 출처가 있다
- [ ] 모든 차트·표에 데이터 출처가 있다
- [ ] 휴대폰 미리보기에서 차트·지도·표가 잘리지 않는다
- [ ] 발행하기의 점검 결과가 0건이다
- [ ] 웹에 올린 주소로 열어 유튜브·Flourish·지도가 모두 보인다
- [ ] 작업 파일(.json)과 발행 파일(index.html)을 둘 다 보관했다
- [ ] 기사 끝 크레딧에 제작진 역할과 자료 출처를 적었다

# 7. 수업에서 쓰기 (교수·강사용)

## 편집기 배포

편집기는 `index.html` 파일 한 개입니다. 웹에 올리면 학생들이 주소 하나로 열고, 수정사항도 한 번에 반영할 수 있습니다.

1. 폴더에 `index.html`을 넣고 `app.netlify.com/drop` 에 끌어다 놓습니다. (GitHub Pages도 가능. 5장 참고)
2. 나온 주소를 학생에게 공유합니다.
3. 편집기를 고쳐 다시 올릴 때는 같은 사이트의 Deploys 화면에 폴더를 다시 끌어다 놓으면 주소는 그대로입니다.

학생의 작업 내용은 서버로 전송되지 않고 각자 브라우저에만 저장됩니다. 학생 정보를 수집하지 않지만, 그만큼 학생이 작업 파일(.json)을 직접 보관해야 합니다.

## 첫 수업에서 안내할 것

- 자동 저장은 그 컴퓨터의 그 브라우저에서만 유지됩니다. 실습실 컴퓨터를 쓸 때는 수업 종료 전에 **작업 파일 저장**을 하도록 하세요.
- 조별 작업은 한 번에 한 사람만 고치고 .json 파일을 주고받게 하세요. 동시에 고치면 한쪽 내용이 덮어쓰입니다.
- Flourish·구글 시트·유튜브는 무료 계정이 필요할 수 있어 미리 가입해 두게 하세요. 수업 시간에 가입하면 편집이 시작도 전에 끝납니다.
- 데이터와 사진의 출처 표기, 저작권, 취재원 동의 원칙을 함께 안내하세요.

## 과제 설계 예시

아래는 예시이며, 수업 목표에 맞게 항목을 빼고 더하세요.

| 요소 | 예시 기준 | 편집기 블록 |
|---|---|---|
| 기본 구성 | 제목·부제·기자·크레딧, 본문 블록 10개 이상 | 표지, 본문, 소제목 |
| 데이터 시각화 | 차트·지도 1개 이상, 출처 표기 | Flourish |
| 표 또는 숫자 | 구글 시트 표 또는 숫자 강조 | 구글 시트 표, 숫자 강조 |
| 현장성 | 사진 1장 이상, 위치 기반 이야기면 지도 | 사진, 구글 어스·지도, 유튜브 |

| 항목 | 비중(예) | 보는 점 |
|---|---|---|

| 데이터 시각화 | 30% | 차트가 주장에 맞고 읽기 쉬운가, 출처가 있는가 |

## 제출 방식

- 학생이 자기 계정으로 올린 주소를 제출하게 하면 기사별 주소가 따로 생깁니다.
- 기사를 한 곳에 모아 보여 주고 싶으면 교수·강사 저장소에 학생별 폴더로 올리는 방법도 있습니다.
- 평가 전에 웹 주소로 열어 유튜브·Flourish·지도가 모두 보이는지 확인하세요. 내 컴퓨터에서 받은 파일로 열면 유튜브가 "오류 153"을 낼 수 있습니다.

# 8. 기사 기획 가이드

좋은 데이터 스토리는 도구보다 질문에서 시작합니다. 편집기에 들어가기 전에 아래 순서로 종이에 먼저 그려 보세요.

1. **질문 한 문장**: 이 기사가 데이터로 답하려는 질문은 무엇인가.
2. **핵심 발견 한 문장**: 숫자가 들어간 답. 이 문장이 제목과 부제가 됩니다.
3. **장면 나누기**: 발견을 3~5개 장면으로 나눠 소제목을 붙인다.
4. **장면마다 증거 하나**: 차트, 표, 지도, 사진, 영상 중 그 장면에 가장 잘 맞는 것 하나를 고른다.
5. **인터랙션은 이해를 도울 때만**: 효과 자체가 목적이 되지 않게 한다.

## 기사 안에서 지킬 것

- 차트마다 제목 대신 **발견을 말하는 문장**을 씁니다. 예: "버스 정류장 10분 밖 가구가 8.4%".
- 모든 데이터에 **출처와 기준 시점**을 적습니다.
- 색은 의미가 있을 때만 씁니다. 긍정은 파랑, 부정은 빨강처럼 규칙을 정해 일관되게 쓰세요.
- 휴대폰에서 보는 독자가 많습니다. 미리보기를 **휴대폰**으로 바꿔 항상 확인하세요.
- 사진·영상에는 대체 텍스트와 출처를 적고, 저작권이 있는 자료는 쓰지 않습니다.
- 이름과 얼굴이 드러나는 취재원은 동의를 받은 경우에만 싣습니다.
